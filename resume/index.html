2024.05 – 재직중

원자력 관련 소프트웨어의 회귀시험과 품질 검증을 담당합니다. 결함 하나가 안전 문제로 이어질 수 있는 분야라, 누가 수행해도 같은 결과가 나오도록 절차대로 시험하고 결과를 남기는 것이 기본입니다.

  • 테스트케이스 설계 — SRS를 분석해 항목별 입력·조건·기대결과를 정의한 테스트케이스 작성
  • SW 회귀시험 수행 — 릴리스·패치마다 수정 기능과 결함 조치 항목을 검증하고 기존 기능 영향 여부 확인
  • 시험 문서 작성 — 고객 제출용 시험 절차서·결과보고서 작성 및 발행
  • 결함 이슈 보고 및 추적 (JIRA) — 재현 절차·시험 환경·기대/실제 결과를 포함해 티켓 등록, 개발팀 조치 후 재검증
  • 원자력 발전소 현장 시험 지원 — SW 현장 설치 시 고객 환경에서 시험 절차서를 직접 수행해 설치 결과 검증
  • 테스트 환경 설치 자동화 프로그램 제작 — 수작업으로 반복하던 설치 절차를 단계별로 정리한 뒤 AI 코딩 도구로 자동화, 작업자별 소요시간 편차를 없애고 팀 공용 도구로 적용

2026.03 – 현재

퇴근 후 시간으로 소비자용 앱과 웹 서비스를 만들어 앱인토스·App Store·Google Play에 출시하고 운영합니다. 무엇을 만들지 정하고, AI 코딩 에이전트(Claude Code · Codex)에 구현을 지시하고, 결과를 검증하고, 내보낼지 판단하는 것이 제 일입니다.

  • 앱인토스 미니앱 18개 · App Store·Google Play 앱 14개 · 웹 서비스 2개 출시·운영 (2026년 9월 기준)
  • 미니앱 합산 7월 MAU 11,612명, 3월 첫 출시 이후 8월까지 누적 신규 사용자 31,697명
  • App Store 심사 통과 버전 73개 — 연령등급·ATT 등 반려 대응과 재제출까지 전 과정 직접 처리
  • 빌드 → 스토어 업로드 → 심사 제출을 App Store Connect API · Android Publisher API 스크립트로 자동화, 반복 릴리스의 수작업 제거
  • 출시 후 MAU·유입 경로·리텐션을 보고 유지·개선·중단을 결정, 성과 없는 앱은 정리
  • 유튜브 채널 바이브빌더 운영 — 비개발자 대상 AI 도구 활용 콘텐츠

운영·검증 사례

  • Android 릴리스 빌드 실행 즉시 크래시 로드 투 트레블 · 2026.07
    문제디버그 빌드와 iOS는 정상인데 Google Play용 릴리스 빌드만 실행 직후 종료. 1 to 50은 같은 증상으로 Play 심사에서 "broken functionality" 반려.
    원인R8 코드 축소가 광고 SDK가 리플렉션으로 생성하는 androidx.work / Room 클래스를 제거. mapping.txt 부재와 dex 내 클래스 존재 여부 대조로 확인.
    조치keep 규칙 추가 후 같은 구성의 1 to 50 · SumDash에도 선제 적용. "릴리스 빌드 실기기 실행 확인"을 배포 전 점검 항목으로 문서화.
  • App Store Guideline 2.1 반려 — 권한 프롬프트 미표시 2026.06
    문제심사 기기에서 앱 추적 투명성(ATT) 권한 프롬프트가 뜨지 않아 반려.
    원인프롬프트를 앱이 활성 상태가 되기 전에 호출해 iOS가 요청을 무시.
    조치앱 라이프사이클 활성화 이후로 호출 시점을 옮기고 재제출, 승인.
  • App Store 2.3.6 연령등급 반려 2026.07
    문제연령등급 설문에 광고 포함 사실이 신고되지 않아 자동 스캔에서 반려.
    조치메타데이터의 광고 항목을 정정해 재제출, 승인. 이후 신규 앱 제출 체크리스트에 항목 추가.
  • 출시본과 소스 트리 불일치 발견 마이포폴 · 2026.08
    문제스토어 라이브 버전(1.0.9)이 로컬 git 트리보다 7개 버전 앞서 있음을 빌드 전 대조에서 발견. 그대로 빌드했으면 출시된 기능이 사라진 채 배포될 상황.
    조치"빌드 전 스토어 버전·브랜치 대조"와 "배포 즉시 커밋·푸시"를 배포 절차의 고정 단계로 추가.
